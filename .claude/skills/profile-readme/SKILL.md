# Profile README maintenance

This repo is the GitHub profile README. Hero = neofetch-style SVG card
(synthwave portrait + spec list), then project cards, link badges, Medium
feed, stats widgets. Everything visual is generated by scripts — never
hand-edit SVGs in `assets/`.

All commands run from repo root. Skill scripts live in
`.claude/skills/profile-readme/scripts/`.

## Operations

| Want to... | Do |
|------------|-----|
| See / swap top-3 showcased repos | `python3 .claude/skills/profile-readme/scripts/set_projects.py --list` then `... set_projects.py RepoA RepoB RepoC` |
| Edit a card spec line (role, uptime, skills) | `python3 .claude/skills/profile-readme/scripts/set_spec.py --list` then `... set_spec.py --label Uptime --value "..."` |
| Rewrite the summary paragraph | `... set_spec.py --summary "markdown text"` |
| Refresh live numbers (repo count, stars, descriptions) | `python3 scripts/generate_neofetch.py && python3 scripts/generate_project_cards.py` |
| Add a link badge | One line in the `> cat ~/connect` block — pattern + palette in `references/content-map.md` |
| Add/inspect a widget | Read `references/widgets.md` FIRST — public instances die; two are already dead |
| New profile photo | Manual-heavy; follow "Re-measuring for a NEW PHOTO" in `references/architecture.md` |
| Understand the SVG pipeline before changing it | `references/architecture.md` |
| Find where a fact/value lives | `references/content-map.md` |

## Hard rules

1. **Verify before push, always**:
   `python3 .claude/skills/profile-readme/scripts/verify.py` — XML validity,
   no external refs inside SVGs, README assets exist, every widget URL
   answers. Non-zero exit = do not push.
2. **`assets/source/` is gitignored** (private photos). Never force-add it;
   the portrait ships baked inside the generated SVGs.
3. **Facts stay grounded.** Spec values have provenance (content-map.md).
   Don't invent skills, numbers, or employer mentions — employer name is
   deliberately absent.
4. **Silhouette polylines are measured, not designed.** Don't "improve" the
   head outline with invented curves (architecture.md explains the two
   incidents behind this rule).
5. **Blog block belongs to the GitHub Action** — never hand-edit between
   `BLOG-POST-LIST` markers.
6. Requires Pillow + network. Visual changes: preview via Artifact
   (data-URI embed) before committing — no local SVG renderer exists.

## Agents

- `readme-updater` — performs any operation above end-to-end (edit →
  regenerate → verify → report diff). Use for delegated update requests.
- `readme-reviewer` — read-only gate: runs verify.py, inspects diff and
  extracted portrait, reports pass/fail. Run before every push.
